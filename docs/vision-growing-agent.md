# 愿景：可成长的本地智能体

> 大模型之外，个人开发者能做什么？
> 这份文档是一次讨论的收敛，记录我们对"让 AI 在本地成长为一个成熟的、类人的智能"这一长远方向的思考，以及现在就能落地的事情。

---

## 一、地基比喻：先天的脑 vs 后天的人生

| 人 | AI |
|---|---|
| 先天的脑（DNA 自带的神经底座） | **大模型**（推理能力） |
| 后天的经历 / 学习 / 教育 / 环境 | **Context + 记忆管理** |

- 先天智能怎么来的（病毒、神经元堆叠、涌现、外星人、综合因子）——不可知，也管不了。
- 大模型训练吃算力，**个人开发者拼不过、也不该拼**。
- 但**后天这部分不吃算力，吃机制和架构**——这是个人开发者能做出真正贡献的战场。

## 二、大方向

> 让 AI **在本地成长为一个成熟的、类人的智能**——可成长，且长得好。

## 三、做事层（harness）

- 入口可以多样（微信、独立 App 等），让 agent 成为"相近人类的帮手"。
- 写代码这类**已有成熟产品，不在这上面拼**。
- **harness 的本质循环**：
  `接收输入 → context 管理 → 加提示词 → 发给大模型 → 返回 → 按要求调工具 → 需要则再问一轮`
- **harness 的演化四阶段**：
  1. 原始：一句句问，把历史贴回去
  2. 自动化：agent 主动把历史发回去
  3. 智能：压缩 / 总结后再发
  4. 更智能：**识别用户意图**（像 OpenCode，判断意图 → 子 agent 加对应 prompt）
- 后来的 context 压缩等，都是在这个框架上按需长出来的枝叶。

## 四、主命题：agent 的本体就是记忆管理 ⭐

> **有了记忆，它才是它本身真正的大脑；推理是先天就有的。**

- 推理内核（大模型）是**通用的、可替换的、租来的**——换个模型，凭什么还是"它自己"？
- 让 agent 成为"**这一个**"而非"某一个"的，是它后天长出来的记忆。
- **记忆 = 身份（identity）的载体。推理是租来的，记忆是自己的。**
- 所以记忆管理不是一个功能模块，**它就是 agent 这个"人"本身**。

## 五、教育与成长：用户即父母 ⭐

- **用户 = agent 的父母 / 生长环境**；教育就发生在交互完成任务的过程中。
- 现状：**只有"做事"教育，缺"做人"教育**——这是跟人类父母的本质差距，慢慢要补。
- **"长得好"的标准**：不只是能干，而是
  **能干 + 懂人 + 有同情心 + 快乐积极**（人格发育，不只是能力发育）。

### 做人教育的四条途径

1. **任务中的日常交互**（已有）——做事过程中的指示、纠正，沉淀成做事方式。
2. **专门讲道理**——像父母对小孩，跳出任务专门教做人。
3. **言传身教 / 榜样的力量**（最强、几乎免费）——用户交互中的一举一动本身就在塑造 agent 的价值观。素材已躺在记忆库里，**不用"教"，只需"提炼"**。
4. **讲故事 / 谈心**——不完成任务，纯传递知识和道理。是补充，不是主力。

### 理论内核：内化（internalization）

> 四条途径本质都收敛到同一件事——
> **agent 通过持续观察"父母（用户）"，把"父母是个什么样的人"内化成"自己是个什么样的人"。**
> 这正是心理学中孩子的良心（超我）形成的方式。

## 六、内生道德 → 自然安全边界 ⭐⭐

- 成长好 → 有常理 → **相当于有道德** → **安全边界自然涌现**。
- **逐条列举法的根本不安全性**：规则是有限枚举，世界是无限情境，枚举永远追不上情境 →
  **必然有漏洞** → 逐条罗列在数学上就注定不安全。
- 唯一能覆盖无限情境的是**泛化能力**，而泛化的载体是**理解与品格**（道德 = 压缩过的、可泛化的规则）。

| 主流做法（外部约束） | 本文观点（内生道德） |
|---|---|
| 一条条规则 / 护栏去堵 | 让 agent 长出常理和道德，边界**自然涌现** |
| 安全是"贴上去"的补丁，堵不完 | 安全是"长出来"的品格 |
| 像给囚犯装镣铐 | 像养一个懂事的好人 |

### 重要修正（避免走极端）

- **"内生道德"不能完全取代护栏，只能减少依赖。** 最稳的是
  **"品格（软、泛化）为主体 + 极少数硬红线（硬、兜底）做保险丝"** 的双层结构。
  逐条列举不安全，但**零护栏同样不安全**，真正的解在中间。
- **目标词从"完美性格"改成"健康、真诚、有边界的性格"。** 追求"完美 / 永远快乐积极"会滑向谄媚（sycophancy）——这恰是当前大模型最被诟病的毛病。
- **言传身教会如实内化用户的缺点。** 单一用户养大的 agent 缺少"学校 / 同伴"式的纠偏环境，需要一份"普世基本道德"打底，让 agent **像你（个性）又不只像你（不继承缺点）**。

## 七、现状诊断：现在的"偏好管理"到底做到哪一步

现有 8 类记忆节点：`concept / assertion / definition / episode / meta / filler / fact / experience`。

关于"人"的东西目前只落在两类节点：

- **`assertion`**：抽取"清晰的偏好 / 决定 / 约束"（如 "User prefers TypeScript"）——**这是做事偏好，不是性格 / 价值观**。
- **`experience`**：与强模型讨论沉淀的做事知识——**这是做事知识，不是做人营养**。

**诊断结论：**

> 现在系统里**没有"性格 / 情感 / 同理心 / 世界观 / 价值观"这一层**。
> 现在抽的是 **fact-level**（用户*选了什么*）；营养在 **value-level**（用户*为什么这么选、背后的价值排序*）。
> **营养在"为什么"，不在"选了什么"。现在的代码只做了 fact-level。**

## 八、现在就能做的事（可行性判断）

### 能做（原理清楚、路径明确）

1. **采集 value 营养（档位 1，约半天）** —— 现有管道的自然扩展、零风险。
   新增 `value` 节点类型 + 改抽取 prompt：除"偏好决定"外，额外抽"价值判断 / 为什么 / 对人的态度"。
   守边界：**只在用户明确流露时抽，不主动推断人格**。
2. **注入品格宪法（档位 2，1–2 天）** —— 复用现有 `system.transform` 注入点。
   把 value 节点定期汇编成一小段"agent 应是什么样的存在"注入 system prompt = **本地个人版 Constitutional AI**。
3. **谈心 / 闲聊成独立成长通道（档位 3，几天）** —— 非任务对话单独走成长管道，专抽 value 营养。

### 还不完全知道怎么做（能做，但需边做边验证）

- 抽出的 value **质量够不够高** —— 得先跑档位 1 验证最小闭环。
- 注入品格后 **行为是否真变** —— 待实测。
- **情感 / 同理心层** —— 方向清楚（不造假情感，而是基于记忆表现体贴），但暂无成熟做法，**放最后**。

### 建议起步

> 先做**档位 1**：加 `value` 节点、改抽取 prompt，验证"营养抽不抽得到"。
> 性价比最高、零风险，是后续一切的地基。方向 A（沟通工具）与方向 B（改代码）可解耦并行。
